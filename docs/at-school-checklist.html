What to do at school

H₂O — Towards 2040 · Mathematics strand · written 16/08/2026

Everything on this page needs something you can only get at work: a fleet laptop, the school network, the printer, a colleague, or a decision. Nothing here needs me. The first item is the only one that can still change the design, so do it before the others even if you do nothing else that day.

Tonight, before you goTwo things to bring

  • Print the staff sheet from this machine node scripts/make-staff-sheet.mjs, then print private/staff-sheet.html. It has to be this machine: private/ is git-ignored, so a fresh clone at school has no sheet and no codes. Print one copy per supervising adult plus a spare.
  • Print the programme leaders' pack docs/programme-leaders-pack.html, four sides. Print double-sided.

Do this first · 20 minDoes the storage survive a restart?

  • Run the probe on a fleet laptop, in Edge, signed in as a student would be iggs-tlelacheur.github.io/Y8EOYP2026/docs/soe-probe.html — press Write the probe, then follow its four steps. It touches nothing beginning h2o.v1., so it is safe on a laptop with real work on it. Close Edge with the X or Ctrl+W, never End Task. A killed browser loses unflushed data and reports a failure that is not real.
  • Then reboot the laptop and read it back a second time The restart and the reboot are different tests. A policy that clears on exit shows up in the first; a profile that is rebuilt at logon shows up only in the second.
  • Check edge://policy while you are there Search it for ClearBrowsingDataOnExit, ClearCachedImagesAndFilesOnExit and anything mentioning Site Data. The probe asks you for what you found. If the page is locked down, a screenshot of it is enough.
  • Send me the block it prints The probe ends with a verdict and a paste-ready block for docs/SOE_NOTES.md. Send it whichever way it survives. If it survived, nothing changes and we carry on. If it did not, stop and tell me before anything else on this page: the progress model moves onto the crew file and the badge design moves with it. That is a decision, not a patch.

Same laptop, next 30 minDoes the site work on the fleet?

  • Sign in with a real ID and a real password iggs-tlelacheur.github.io/Y8EOYP2026/ — use your own row from the roll. The hub should greet you by display name and say Data set N of 6 at the bottom.
  • Get the door wrong on purpose, twice A wrong ID must say not on the list; a wrong password must say does not match. Two different messages is the whole point of splitting them — if they read the same, a student spends the lesson fixing the wrong half.
  • Do Lesson 1's card sort with a finger only Eight cards into three boxes, no mouse, no pen. Then do it again with the keyboard only — Tab to a card, press 1, 2 or 3. Both routes exist on purpose and both have to work on this hardware.
  • Drag the line of best fit in Lesson 5 with a finger The single most touch-sensitive thing in the build. Both handles, on the touchscreen, with a finger rather than a stylus. If it feels fiddly at all, say so — that is a real finding, not a nitpick.
  • Watch for a control that never comes back Anywhere a button greys out and stays greyed out is the failure mode that costs a lesson. Note the page and what you had pressed.

Needs a second laptopThe crew Card on OneDrive

This is the least tested part of the build, because it cannot be tested anywhere but here. The Card is a shared file in the crew's Teams folder, edited by twelve to fifteen students and handed to a film crew. Nothing about that changes even if the storage probe passes.

  • Make a Card in a real Teams or OneDrive folder card.html → save → put the .h2ocard in a synced folder, not in Downloads. Close the tab, reopen the Card, confirm it offers the same file back without asking you to find it again.
  • Open the same Card on two laptops and type on both Expect a warning naming whoever saved last, and a Save a copy button. It is a soft lock on purpose: the point is that two students talk to each other, not that the site stops one of them.
  • Save while OneDrive is still syncing, and while it is offline Turn the wi-fi off mid-save if you can. Everything that touches that file is on a six-second clock, so it should tell you it could not write and let you carry on. A stalled save that leaves the button dead is the bug I most expect to exist.

The printer, not a PDFPrint three things

  • A certificate certificate.html, landscape, one sheet. It was measured at 202 mm against 210 mm of A4, but that was a measurement, not a print. Until the dates and signature are set it prints visible placeholders, which is intended.
  • A Card that is only half finished It has to print at any stage, not only at the end. Two sheets, a chart on each.
  • A recording sheet from the table tool tools/table.html. Students take this one out of the room and write on it by hand, so the lines have to be wide enough to write in.

15 min with a colleagueThe test that matters most

  • Hand staff.html to someone who does not teach maths Give them no briefing. Ask them one question: "is this crew's work good enough?" for each of the six rooms, using only what is on the screen. Anywhere they hesitate, the crib note is not finished. Tell me which room and what they asked you, and I will rewrite it. Four of the six lessons are supervised by someone in exactly that position, so this is worth more than any other fifteen minutes on this page.

Only you can get theseDecisions and content

  • Programme dates and a signature — data/programme.json Four values: startDate, endDate, signatory, signatoryRole. Dates as dd/mm/yyyy. Nothing else is blocking the certificates.
  • Crew names, and how many index.html still offers placeholder Crew 01–12. Names are held apart from identity, so a student can move crews later without losing a badge.
  • A Teams or OneDrive folder per crew, with the crew able to write to it Ask whoever runs Teams for the programme. The Card lives there; without it the crews have no shared artefact.
  • Confirm which four lessons have no maths teacher in the room The build assumes L2 to L5. If it is a different four, the crib notes stay right but the deck timings do not.
  • Rows 199–201 of private/roll.csv Spare passwords with no ID beside them, skipped at build time. Nothing to do unless they are real people.

Hand overThree conversations

  • The programme leaders — give them the pack docs/programme-leaders-pack.html. It says what the strand is, what it needs from the programme, and what happens to student data. The last one is the question they will actually ask.
  • The supervising staff — one printed sheet each, and the page staff.html is not linked from anywhere a student goes. Show them the crib notes, the badge rules, and where the staff codes are. Tell them the codes are on paper only and are not to be sent anywhere.
  • The film strand — tell them the exports exist Every chart tool exports 1920 × 1080 with the type large enough to film. Whether a chart appears in the film is their rubric, not a maths criterion.

Please do notFour things

  • Do not email the staff sheet, or put it in Teams It carries all seventy-two answers and the four staff codes. Paper, carried.
  • Do not use the old codes Every staff code written down before 16/08/2026 is dead. The first set reached the public repository and was retired rather than re-hidden, so those four open nothing now. Throw away anything you wrote them on. The live four are on the staff sheet you print tonight, and nowhere else.
  • Do not commit anything from private/ It is git-ignored. That is the only thing standing between the answer key and a public site.
  • Do not push to main during a lesson A push is a deploy and there is no staging. A broken push during Lesson 3 is a broken Lesson 3 for the whole cohort.
